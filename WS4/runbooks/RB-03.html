Restarting the billing service

Before you start

The billing service runs on app-prd-01 to app-prd-08 behind the load balancer. A restart on one host is safe during the day; a restart on all hosts at once stops invoicing for about two minutes and must be announced in the change channel first.

Check the reason for the restart. If the service stopped because of a database error (codes X7Q-4421 or X7Q-4412), fix the database side first with RB-01, otherwise the service stops again after the restart.

Make sure you have sudo rights on the host and that nobody else is working on the same host: look at the maintenance board and write your name there. Take the host out of the load balancer pool with the drain script, so that no new requests reach it while you work. The drain script waits until the open requests are finished, which normally takes less than thirty seconds. Keep the change channel open, so that the on-site colleagues can see what is happening. If the host does not leave the pool, stop here: the load balancer may be in maintenance, and a restart without a drain cuts the open invoice requests.

Procedure

  1. Drain the host: sudo /usr/local/bin/lb-drain billing
  2. Restart the service: sudo systemctl restart billing
  3. Watch the log for one minute: journalctl -u billing -f. The line 'Started billing service' must appear and no ERROR line after it.
  4. Put the host back in the pool: sudo /usr/local/bin/lb-undrain billing
  5. Repeat on the next host only when the previous one serves requests again.

Checks after the restart

Open the billing dashboard and check that the error rate is back below 1% and that invoice batches close again. Write the restart, the host and the reason in the change log.
