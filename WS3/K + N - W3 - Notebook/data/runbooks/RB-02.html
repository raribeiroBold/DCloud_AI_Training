pg_wal filling up on PostgreSQL

Why pg_wal grows

PostgreSQL keeps write-ahead log (WAL) files until nothing needs them. pg_wal grows without limit when a replication slot is no longer consumed, when archive_command keeps failing, or when wal_keep_size is set too high. Never delete files in pg_wal by hand: the database needs them to recover after a crash.

What to do

  1. Check the slots: SELECT slot_name, active, restart_lsn FROM pg_replication_slots; Drop a slot that is inactive and no longer needed with pg_drop_replication_slot().
  2. Check archiving: SELECT failed_count, last_failed_wal FROM pg_stat_archiver; If failed_count grows, fix archive_command (space or access on the archive target).
  3. Check SHOW wal_keep_size; against the size of the volume.
  4. Run CHECKPOINT; and check again with du -sh /var/lib/pgsql/data/pg_wal: files no longer needed are removed or recycled.
