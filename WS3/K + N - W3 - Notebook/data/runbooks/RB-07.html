OOM killer on database hosts

What happened

When a host runs out of memory, the Linux kernel's OOM killer stops the process using the most memory, usually a postgres backend on a database host. The kernel log shows 'Out of memory: Killed process', and the postmaster logs that a server process was terminated by signal 9 and restarts all sessions. Connections fail for one or two minutes while the database recovers.

What to do

  1. Check that PostgreSQL is accepting connections again: pg_isready
  2. Find the query that used the memory in the PostgreSQL log around the time of the kill.
  3. Lower work_mem or max_connections if the kill repeats, and open a ticket for team-dba.
